# Запуск базовой информационной системы

Из корня проекта на Python 3.11+:

```powershell
uv sync --extra ocr --extra ner-benchmark
$env:PII_SOURCE_ROOT = 'C:\путь\к\каталогу\документов'
uv run python -m app.api.main init-db
uv run python -m app.api.main serve
```

При `init-db` ввести логин и пароль администратора длиной не менее 12 символов в интерактивном приглашении. Команда создает администратора только в пустой БД; повторный запуск не добавляет нового. Пароль не передается аргументом команды; в SQLite хранится PBKDF2-HMAC-SHA256 с отдельной случайной солью. Затем открыть `http://127.0.0.1:8765`. Браузер запросит учетные данные через HTTP Basic. Запуск привязан только к loopback; при переносе за пределы локального компьютера необходим TLS.

SQLite создается в `var/catalog.sqlite3`, технический кэш ключ-значение `dbm` — в `var/analysis_cache*`. Кэш хранит только SHA-256 документа, статус и количество обнаружений по типам, без исходного текста и значений ПДн. Каждый запрос анализа заново извлекает текст и вычисляет сущности; подробный ответ не берется из кэша. Каталог и кэш не добавляются в Git.

Откройте `/register` для самостоятельной регистрации оператора. Пароль должен содержать не менее 12 символов; новая учетная запись никогда не получает права администратора. Администратор меняет роли на главной странице. Основные роли: `admin` управляет пользователями и всеми записями, `operator` управляет собственными источниками и записями, `auditor` только читает каталог и журнал. HTTP Basic подходит только для локального запуска; пароль передается в каждом запросе, поэтому внешний доступ требует TLS и отдельного развертывания.

Через главную страницу можно зарегистрировать каталог внутри `PII_SOURCE_ROOT`, сканировать его, создать/изменить/удалить запись, искать и сортировать каталог, проверить найденный файл каталога или загрузить отдельный документ. Для файла каталога система сверяет фактический SHA-256 с инвентаризацией и просит пересканировать изменившийся источник. Удаление записи **не удаляет исходный файл**. Загрузка сохраняет метаданные и сводку анализа, а содержимое файла удаляется после запроса. Неизвестные даты и контрольные суммы остаются `null`; новые файлы каталога получают категорию `unclassified`, которую можно изменить. Windows-владелец читается из ACL; при недоступности атрибута возвращается `null`. На POSIX `ctime` не принимается за дату создания: используется `birthtime`, если файловая система его предоставляет.

REST-маршруты: `POST /api/register` (публичная саморегистрация оператора); `GET /api/users` и `PATCH /api/users/{id}/role` (администратор); `GET /api/audit` (администратор/аудитор); `GET,POST /api/sources` и `POST /api/sources/{id}/scan`; `GET,POST /api/objects`, `GET,PATCH,DELETE /api/objects/{id}`, `POST /api/objects/{id}/analyze`; `POST /api/analyze`, `POST /api/documents` и `POST /api/preview-page`. Все остальные маршруты требуют входа. Для поиска объектов доступны `q`, `file_type`, `category`, `min_size`, `max_size`, `accessed_before`, `sort_by`, `descending`. Анализ поддерживает UTF-8 TXT, DOCX, PDF и изображения. Ответ содержит `segments` с извлеченным текстом, `entities` с меткой, текстом, смещениями, источником, оценкой и страницей. Для сопоставленных слов PDF возвращаются координаты в пунктах страницы, для изображений — в пикселях; при неуверенном сопоставлении `bounding_box=null`. Режим `mode` равен `hybrid` или `deterministic_only`. Содержимое и значения ПДн присутствуют только в защищенном ответе; в SQLite и кэш они не записываются.

После загрузки открывается отдельное окно просмотра: PDF и изображения показаны как страницы с рамками на местах находок; для них нужна доступная координатная привязка. TXT показывается целиком с выделениями. DOCX показывается с абзацами, таблицами и прямым форматированием текста; точная пагинация Word и встроенные изображения без дополнительного конвертера не воспроизводятся. Кнопка «Открыть документ с выделениями» повторно открывает просмотр, пока страница браузера не закрыта. `POST /api/preview-page` обрабатывает файл в памяти и не создаёт запись каталога.

Для PERSON нужен точный локальный snapshot из `configs/semantic_person_frozen_v2.json`:

```powershell
uv run --with huggingface-hub python -m scripts.fetch_semantic_models --model ru_pii_ner_gliner2_5
```

Загрузка должна дать SHA-256 `48238a57dd048f6e00b157684fc84c0dd35a8dec22b32a588084d260cd66a293`. Сервер проверяет этот хеш, ревизии модели и tokenizer. При недоступности модели выполняются только детерминированные правила; причина явно возвращается в `model_error`, а PERSON не выдается. ADDRESS остается выключенным. Веса лежат в `models/ner` и не входят в Git.

Для OCR нужен установленный Tesseract (на Windows автоматически ищется `C:\Program Files\Tesseract-OCR\tesseract.exe`; альтернативу задает `TESSERACT_CMD`). Русский и английский языковые пакеты можно поместить в `models/ocr/rus.traineddata` и `models/ocr/eng.traineddata` из [официального tessdata_fast](https://github.com/tesseract-ocr/tessdata_fast). На этой машине SHA-256 файлов: `rus` — `E16E5E036CCE1D9EC2B00063CF8B54472625B9E14D893A169E2B0DEDEB4DF225`, `eng` — `7D4322BD2A7749724879683FC3912CB542F19906C83BCC1A52132556427170B2`. PDF с текстовым слоем читается без Tesseract; страницы без слоя и изображения проходят OCR.

При первом запуске после предыдущего среза SQLite-схема обновляется автоматически с сохранением старых записей. Перед изменением создается `catalog.sqlite3.pre-stage3.bak` рядом с БД. Копия содержит метаданные и хеши паролей и должна защищаться так же, как основная БД.

Проверка рабочего сценария:

```powershell
uv run --extra test python -m pytest tests/integration/test_system.py -q
```

Для всего набора тестов нужен также тестовый генератор данных: `uv run --extra test --extra test-data python -m pytest -q`.

Метрики экологичности, правила сроков хранения и полное/инкрементальное резервное копирование описаны в `docs/ECOLOGY_STAGES_5_6.txt` и `docs/LIFECYCLE_BACKUP_DEMO.txt`. Перечень функций ролей упрощен относительно методички; решение требует подтверждения руководителя. Локальный demo-сервер `app.api.demo` сохраняется для прежних экспериментов, но не является защищенным приложением.

## Диагностика этапа 4

Контрольный исходный текст `Почта: ivan@example.ru; телефон: +7 999 123-45-67` дал EMAIL (7:22) и PHONE (33:49) через `DeterministicPipeline`. Парсер DOCX извлекал абзацы, PDF извлекал текст страниц либо направлял их в OCR, но TXT отсутствовал. Старый `/api/analyze` запускал только `DeterministicPipeline`, возвращал лишь количества и при повторе отдавал сводку из кэша. Интерфейс показывал этот JSON, поэтому найденное значение и место нельзя было увидеть. Теперь API возвращает сегменты и сущности, а интерфейс подсвечивает их и показывает таблицу. Повторный запрос выполняет inference заново.

Загруженный PERSON checkpoint и tokenizer имеют ревизию `7a410193d83373e61d029944aac77ae47ffb5d9a` и совпадают с frozen snapshot hash. Локальный запуск на новом тексте вернул PERSON и EMAIL с проверенными смещениями; HTTP `/api/analyze` вернул `mode=hybrid` и те же смещения. Отличие среды от сохраненного эксперимента: нынешний inference работает на CPU с другой версией PyTorch, поэтому прежние F1 из `artifacts` не переносим на этот запуск. Для русского OCR потребовались языковые файлы `rus` и `eng`; созданное контрольное изображение прошло Tesseract и дало EMAIL на смещениях 7:22. Показанные проверки подтверждают работоспособность сценария, но не дают оценки полноты на реальном корпусе документов.

## Локальная демонстрация для защиты

Из корня репозитория в PowerShell:

```powershell
uv run python -m app.api.demo
```

Откройте `http://127.0.0.1:8765` и загрузите DOCX. Для PDF и изображений в этой Windows-среде запустите сервер с OCR-зависимостями и явными путями к установленному Tesseract и языкам `rus+eng`:

```powershell
$env:Path += ';C:\Program Files\Tesseract-OCR'
$env:TESSDATA_PREFIX = "$env:LOCALAPPDATA\Tesseract-OCR\tessdata"
uv run --extra ocr python -m app.api.demo
```

Пути действуют только в текущем окне PowerShell. Перед запуском можно проверить OCR командой `tesseract --list-langs`: должны появиться `eng` и `rus`. Цифровой PDF с текстовым слоем обрабатывается без Tesseract. Сервер доступен только с этого компьютера (`127.0.0.1`); завершение — `Ctrl+C`.

Интерфейс показывает страницы PDF и изображений с рамками поверх распознанных слов. Зелёная рамка означает `accept`, жёлтая — `review`; нажатие на находку в списке переводит к рамке. Вспомогательная текстовая копия страницы доступна под превью. Если координаты цифрового PDF не удалось надёжно связать с находкой, подсветка остаётся только в текстовой копии. Для DOCX показано текстовое превью по абзацам с подсветкой: исходная вёрстка и колонтитулы DOCX не воспроизводятся. Визуальное превью PDF ограничено 20 страницами; остальные страницы доступны в текстовом виде. Правила `deterministic_v3` не ищут `PERSON` и `ADDRESS`; балл детектора не является калиброванной вероятностью. Загруженный файл удаляется после запроса, результаты не сохраняются.
