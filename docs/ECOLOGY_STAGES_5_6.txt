# Этапы 5–6: методика отчёта

Источник методики: `КР_ЭД_Методичка_Версия_002.docx`, пункт 1.9; В. Г. Абашин, *Экология данных* (2025), раздел 2.1. В монографии токсичность информационной системы включает данные, алгоритмы, вычисления и человеческий фактор. Здесь измеряется только риск хранения данных, прежде всего ПДн; это не общая оценка всех составляющих.

`GET /api/ecology` рассчитывает дубликаты, актуальность и индекс для доступных пользователю **присутствующих файлов каталога** (`origin=directory`, `availability=present`). Архивные файлы учитываются отдельно в объёме и экономических оценках; ручные записи и загрузки не хранят файл. Оператор видит только свои объекты; снимки сканирования видны аудитору и администратору. `registered_snapshots` — исторические показания инвентаризации, не сумма объёмов и не независимые снимки по отделам. Размер считается в байтах по каталогу; пропущенные размеры показываются отдельно. Сжатый размер и производные/резервные копии уже есть в каталоге, но пока не имеют доказанной классификации, поэтому их доли и коэффициент сжимаемости не выдаются за измеренные.

Полные дубликаты: один SHA-256 у двух или более разных путей. Сохраняемым экземпляром условно считается запись с самой ранней датой изменения (при равенстве — меньший ID); остальные — кандидаты. SHA-256 подтверждает совпадение байтов на момент сканирования, но не право удалить копию. Версии — лишь вероятные пары/группы: одна директория, совпадающая основа имени после конечного маркера `vN`, `versionN`, `версияN`, разные SHA-256. Это не доказательство происхождения и не оценка освобождаемого объёма. Выявление версий не читает содержимое и пропускает переименования без маркера.

«Тёмные» данные: `accessed_at` старше `dark_days` из конфигурации. Это дата доступа файловой системы, не журнал делового обращения; при её отсутствии статус неизвестен. Изменение настроек файловой системы может исказить оценку. Превышение срока хранения определяется лишь для категорий с явно внесённым сроком в `retention_days_by_category`, по дате создания либо изменения. Пустая карта по умолчанию означает отсутствие утверждённой локальной политики; превышение не означает установленное нарушение закона. Дата в будущем или неизвестная дата не дают положительного вывода. Кандидатам присваивается рекомендация **рассмотреть** архивирование или удаление. `performed_operations` показывает операции жизненного цикла из журнала; сам отчёт не изменяет файлы. Фактическое освобождение физических блоков после удаления остаётся неизвестным, если существуют копии или ссылки.

`possible_reclaim_bytes_upper_bound` — сумма размеров *уникальных ID файлов* в объединении признаков дубликата, темноты и превышения срока, так что файл с несколькими причинами учитывается единожды. При неизвестном размере хотя бы одного кандидата показатель `null`, число таких файлов выдаётся отдельно. Это верхняя оценка по независимым файлам, а не обещанный эффект. Для дубликатов отдельно приводится байтовый объём всех экземпляров сверх одного. При дедупликации хранилища или жёстких ссылках физический выигрыш может быть меньше; без идентификатора физического блока его подтвердить нельзя.

Профиль качества: доля файлов с обнаруженными ПДн и счётчики классов считаются только по завершённым анализам с сохранёнными **агрегированными** счётчиками. Значения ПДн не сохраняются в каталоге. Отсутствие анализа — неизвестное состояние. Доля незаполненных метаданных учитывает владельца, категорию и размер. Доля отклонений от **внутреннего правила срока хранения** рассчитывается только при заданных сроках и известной дате; иначе `null`. Защищённость и другие правила хранения не измеряются. Автоматическая находка ПДн и истечение заданного срока — поводы для проверки, не установленные правонарушения и не универсальная «токсичность».

Индекс: `100 × (1 − Σ(wᵢ rᵢ) / Σwᵢ доступных)`, где все `rᵢ` лежат в `[0,1]`, большее значение означает больший риск, а индекс 100 означает меньше измеренного риска. Входы: доля лишних байтов по SHA-256; доля тёмных среди файлов с известной датой доступа; доля файлов с неполными метаданными; доля превышений среди файлов с применимым сроком и датой. Рабочие веса каждого риска — 0,25: равные веса выбраны, поскольку доказанной шкалы относительного вреда для этой организации пока нет. Это **не научно установленные коэффициенты**. При отсутствии знаменателя компонент исключается, остальные веса нормируются; `available_weight` и `partial` явно показывают неполное покрытие. При отсутствии всех компонентов индекс `null`. Сравнивать индексы разных охватов без учёта доступных компонентов нельзя. Объём и PII F1 в индекс не включены: объём не является риском сам по себе, а F1 измеряет детектор, не свойства хранения. Изменение порогов, категорий и состава каталога меняет индекс.

Профиль PII-экспериментов показывается отдельно. На PII-Bench (`artifacts/pii_bench_hybrid_replay_v1.json`, view `entity`, 910 документов) получено TP=667, FP=45, FN=33: micro Precision=0,9368, Recall=0,9529, F1=0,9448; macro F1=0,9426. Оценены 9 из 12 канонических классов; ADDRESS, CVC, TOKEN исключены. Это воспроизведение записанных PERSON-предсказаний с детерминированным слоем, а не новый запуск модели. На другом корпусе (`artifacts/redmadrobot_frozen_01/metrics.csv`) micro Precision=0,7050, Recall=0,4392, F1=0,5412; охват и разметка там другие. Нельзя переносить эти цифры на документы организации без репрезентативного размеченного корпуса и проверки смещения форматов, языков, OCR и частот классов. Сводный F1 не смешивается с индексом экологичности.

Вопросы для согласования с руководителем: (1) допустимо ли вместо доли резервных и производных копий показывать «не измерено» до маркировки? (2) допустимо ли вместо неподтверждённой доли нарушений хранения показывать долю превышений **внутреннего** срока как сигнал для проверки? (3) нужны ли в индексе дополнительные измерения доступа/защищённости после появления политики и журналов? (4) какие категории, сроки, целевые пороги и веса утверждены для эксперимента? (5) какой размеченный набор документов организации допустим для оценки переноса PII-детектора?
